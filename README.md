# 제주 1인 세대 살핌 보고서

매달 "이달 먼저 살펴볼 동"을 알려 주는 월간 보고서입니다. GitHub Actions가 매일 새벽 한 번 공공데이터포털을 확인해, 새 달 자료가 나오면

1. `data/single.json`에 그달 자료를 쌓고
2. `scripts/report.py`가 기준(80세 이상 증가, 청년 급증, 80세 이상 비중, 1년 증가)을 계산해 보고서를 만들고(외부 AI 없음, 문장 틀)
3. 화면(index.html)과 `reports/연월.md`에 저장한 뒤
4. 같은 보고서를 저장소 **Issues**에 "월간보고서" 라벨로 올립니다. 저장소를 Watch 해 두면 담당자 메일로 옵니다.

- 자료: 행정안전부_법정동별(행정동 통반단위) 성/연령별 주민등록 1인세대수 (공공데이터포털 15108085)
- 기준: 주민등록 월말 기준, 한 달에 한 번 바뀜. 실시간 자료가 아닙니다.
- 처음 들어 있는 `data/single.json`은 **교육용 가상 데이터**입니다. 키를 넣고 실행하면 실제 자료로 바뀝니다.

## 올리는 순서

1. 새 공개 저장소(예: `jeju-single`)를 만들고 `index.html`, `README.md`, `data` 폴더, `scripts` 폴더를 올립니다. 폴더째 끌어 놓으면 구조가 그대로 올라갑니다.
2. Settings > Pages에서 main, / (root)로 켭니다.
3. Settings > Secrets and variables > Actions > New repository secret. 이름 `PUBLIC_API_KEY`, 값은 공공데이터포털 인증키(Decoding). 키가 없으면 이 단계는 건너뛰고 가상 데이터로만 돌려 볼 수 있습니다.
4. Settings > Actions > General 맨 아래 Workflow permissions를 **Read and write**로 고르고 **Save**.
5. Settings > General > Features에서 Issues가 켜져 있는지 확인합니다.
6. Actions 탭 > **New workflow** > **set up a workflow yourself** > 파일 이름을 `collect.yml`로 > 편집창을 비우고 `collect.yml_붙여넣기용.txt` 내용을 붙여 넣고 Commit.
7. Actions 탭 왼쪽 **1인 세대 월간 보고서** > Run workflow. 초록 체크가 뜨고 Issues에 "○년 ○월 말 1인 세대 살핌 보고서"가 올라오면 성공입니다.
8. `https://아이디.github.io/저장소이름/`을 엽니다.

## API 설정 (11/5 실제로 확인한 값)

`scripts/collect.py` 맨 위 `CONFIG`에 들어 있습니다.

| 항목 | 값 |
| --- | --- |
| 요청주소 | `https://apis.data.go.kr/1741000/stdgSexdAgeOneHh/selectStdgSexdAgeOneHh` |
| 지역 `stdgCd` | 제주시 `5011000000`, 서귀포시 `5013000000` 로 나눠 물음 (제주도 전체 `5000000000`은 자료 없음으로 답함) |
| 단위 `lv` | `3` 읍면동 단위. 리 값은 읍면으로 합침 |
| 기간 | `srchFrYm`, `srchToYm` 연월 (2022년 10월부터) |
| 응답 칸 | `male0AgeHhCnt` ~ `male100AgeHhCnt`, `feml0AgeHhCnt` ~ `feml100AgeHhCnt` 를 화면 나이대로 묶음 |

자료 없음이라고 답하면 다른 조합으로 차례로 다시 묻고, 서버가 늦으면 세 번까지 다시 묻습니다. 지난달 · 작년 같은 달이 빠져 있으면 다음 실행 때 채웁니다.

## 기준 바꾸기

`scripts/report.py` 맨 위 `RULES`의 숫자만 바꿉니다. 화면과 보고서의 기준 설명은 이 숫자를 따라 자동으로 바뀝니다.

| 기준 | 지금 값 |
| --- | --- |
| 80세 이상 한 달 증가 | 지난달보다 10세대 이상 |
| 청년 급증 | 지난달보다 8% 이상이면서 20세대 이상 |
| 80세 이상 비중 높음 | 1인 세대 중 80세 이상 20% 이상, 지난달보다 0.5%p 이상 상승 |
| 80세 이상 1년 증가 | 작년 같은 달보다 15% 이상 |
| 작은 동 빼기 | 1인 세대 300세대 미만인 동은 기준에서 뺌 |
| 이달 먼저 살펴볼 동 | 걸린 기준이 많은 순으로 3곳 |

처음에는 가상 데이터에 맞춰 1년 증가 8%, 작은 동 빼기 없음으로 만들었습니다. 실제 자료(2026년 10월 말)로 돌리니 27곳이 걸리고, 1인 세대 65세대인 동이 한 세대 차이로 "비중 높음"에 걸렸습니다. 제주 80세 이상 1인 세대는 1년에 보통 5% 안팎 늘기 때문입니다. 15%와 300세대로 바꾸니 7곳이 남았습니다. **기준은 실제 자료를 보고 맞춥니다.**

## 알고 쓸 점

| 항목 | 내용 |
| --- | --- |
| 단위 | 법정동(예: 일도일동) 단위입니다. 행정동(예: 일도1동)과 이름 · 경계가 다릅니다. |
| 비율 | 전체 세대수가 없어 세대 수만 비교합니다. 큰 동이 위에 오기 쉽습니다. |
| 기준 차이 | 주민등록 1인 세대는 통계청 1인 가구와 기준이 다릅니다. |
| 쓰임 | 살필 순서의 참고입니다. 위기 가구를 찾아내는 근거가 아닙니다. |
| 키 | Secrets에만 둡니다. 결과 파일과 로그에서는 *** 로 가립니다. |
| 자동 실행 | 매일 한국 시간 새벽 3시. 새 달 자료가 없으면 아무것도 바꾸지 않습니다. 저장소에 60일 동안 변화가 없으면 예약 실행이 꺼집니다. |

## 막힐 때

| 증상 | 해결 |
| --- | --- |
| Actions에 "set up a workflow yourself"가 안 보임 | Pages를 켜 둔 저장소는 시작 화면이 안 나옴. 오른쪽 위 New workflow를 누르면 있음 |
| 워크플로 이름이 `.github/workflows/collect.yml`로 보이고 바로 실패 | 붙여넣기가 비어 있음. 파일을 열어 0 lines면 `github.com/아이디/저장소/edit/main/.github/workflows/collect.yml` 에서 다시 붙여넣기 |
| 초록인데 자료가 그대로 | 받기에 실패해도 초록으로 끝나게 만듦. report > 자료 받기 로그를 봄 |
| 로그에 "NODATA_ERROR" | 그 지역 코드 · 단위 조합에 자료 없음. CONFIG의 tries 조합 확인 |
| 로그에 "timed out" | 공공데이터 서버 지연. 다음 실행 때 빠진 달을 다시 받음 |
| 로그에 "결과 코드 30" 등 | 그 API 활용신청 확인, 승인 뒤 1시간쯤 기다림 |
| 저장 단계에서 403 | Workflow permissions를 Read and write로 하고 Save |
| Issue가 안 올라옴 | Issues 켜기. 이미 보고서를 만든 달이면 다시 올리지 않음 |
| 내 PC에서 두 번 눌러 열면 예시만 보임 | 정상. Pages 주소로 여세요 |

교육용 시연 저장소입니다. 업무에 쓸지와 공개 범위는 기관 보안 담당과 정합니다.
